Summaries: a map of the repository and a guide to every PR

pullspace learns to read a .pullspace/ directory of agent-written HTML pages (one per important directory, plus a guide per pull request), shows them beside the code in a sandboxed frame, says whether each is still true by its git tree hash, and on a PR shows a rewritten page before and after; the two agent skills that write those pages, and this repository's own map, come with it.

Why

Coding agents write code faster than anyone can review it. A diff shows which lines moved, not what the change is for, how it fits the system, or what it quietly makes untrue. The agent that made the change knows all three, so this PR asks it to write them down in the repository, next to the code, in a form pullspace can show at the moment of review: a guide to the PR, and a map of the repository whose pages the PR has to keep true. The user-facing account is SUMMARIES.md.

Two constraints shaped it. pullspace has no server, so everything (freshness included) has to come from the repository and GitHub's API. And a page is somebody else's HTML rendered in the tab that holds the GitHub token, so it has to be drawn somewhere it can reach nothing.

Reading order

  1. FORMAT.md — the contract: the layout, the stamp, and the rules every page follows. Everything in the app reads this format, so start here; the root is stamped with .pullspace left out, which the next two steps depend on.
  2. github.rs — Snapshot::dirs, then snapshot_of: the tree read the app already made now keeps each directory's hash instead of throwing the tree entries away, and adds a root entry computed without .pullspace, only for an untruncated tree. blobs::load re-reads a cached snapshot that predates dirs.
  3. backend/summary.rs — the stamp: meta scans a page's head for its stamp, freshness compares it with dir_sha, drift lists what moved since, and root_stamp rebuilds the root tree object byte for byte, as git mktree does. Check the sort order and mode trimming against git's.
  4. backend/summary.rs — the frame document: the CSP, the one nonce'd script (the link bridge, plus COMPARE_JS on a rewritten page), script_string so the other side can't close that script, and the stripped meta refresh. This is the security boundary; read it most carefully.
  5. ui/summary.rs — the other end of the bridge: the per-load nonce and token, LISTEN_JS (the token must match and the source must be one of our frames), and follow, which maps a link to a page, a file at a line, or the browser. Then frame: sandbox="allow-scripts" and never allow-same-origin.
  6. ui/summary.rs — SummaryPane: loading both sides through ensure_path like any file, the current/out-of-date pills, Before/Both/After on a rewritten page, the "this PR changes files under here and leaves this page" warning, and the on-click drift request.
  7. app.rs — open_summary … close_summary and the two new signals, registered in held!: how a summary shares the middle pane with files and descriptions and keeps its tab. The entry points are small: the ◈ buttons in filetree.rs, the tab in tabs.rs, the welcome button in viewer.rs, and a palette command.
  8. pullspace-change and pullspace-map with their scripts: the writing half. Then the map this PR adds, starting at the root page, which is also the best test of whether the format works.

The map pages are all new in this PR, so pullspace shows them as added, not as before/after. Four of them describe code this PR adds and were brought up to date as it changed: src/backend, src/ui, skills and the root; src had two stale line anchors and a sentence about the frame's script fixed.

Decisions

Freshness is git's tree hash, stamped in the page, over a date, a commit id, or a record kept anywhere. The hash changes exactly when something under the directory does, GitHub's tree read already returns it, and git diff <old-stamp> <new-stamp> tells the agent what moved. A commit id would go stale on every unrelated commit.

The root is stamped without .pullspace, and the app rebuilds that tree itself (sha1_smol, no dependencies). Otherwise writing any page would make the root page out of date. GitHub has never seen that tree, so there is nothing to ask it for. On a truncated tree the root gets no hash and shows as unstamped, because a wrong stamp is worse than none.

A frame with allow-scripts and a nonce'd script, instead of the empty sandbox the HTML Preview uses. Links into the code and between pages are the point of a map, and without a script a click either does nothing or navigates the frame. The frame still has an opaque origin, so even a script that got in could not reach the app's storage. The CSP (default-src 'none', scripts by nonce only) keeps the page's own scripts, handlers and network requests out.

Link messages are checked twice: the random token must match, and e.source must be one of the iframe.summaryframe windows. Any page can post a message to the app, and a followed link opens things.

Before/after is lit by passage, not by word. COMPARE_JS marks the innermost paragraphs, list items and headings whose text the other side lacks. What changes in an explanation is a claim, and a claim is a sentence or a bullet. It runs in the frame over an inert DOMParser copy of the other side, so the app never parses page HTML itself.

"What changed since it was written?" is fetched on click only. It is one tree request, and signed-out users get 60 an hour.

Cached snapshots without dirs are re-read once rather than bumping blobs::VERSION, which would throw away every stored blob to fix one small JSON file per commit.

Relative links resolve against the directory a page describes, not against where the page sits under .pullspace/map/. That is the only reading under which store.rs in the summary of src/backend means what its author meant. The format still asks for /-rooted links.

The skills ship in this repository (skills/, symlinked from .claude/skills/) as plain directories with shell scripts that need only git, sh and awk, so any agent harness can use them and no service is involved.

Risks

The root stamp must equal git mktree's output byte for byte. If GitHub ever reports modes or names differently from what root_stamp expects, every root page shows "out of date" in the app while plan.sh says current. The test checks it against real git mktree output, including a 040000 mode, a symlink, an executable and the src.txt/src ordering case.

One extra tree request per cached commit, once. Every snapshot cached before this change is read again on its first open (blobs::load). That is harmless, but a signed-out user reopening many cached commits spends rate budget on it.

The frame is a security boundary that now runs a script. Adding allow-same-origin to frame, loosening the CSP in frame_doc, or putting page text into the script without script_string would each give a page the token's origin or a way to run code. The nonce and token come from Math.random, once per app load. They only need to be unguessable to the page's author, who cannot run a script to read them.

A large rewritten page is carried twice: each side's srcdoc embeds the other side as a string for the comparison. That is fine at the sizes the format asks for, but a very long page doubles.

The two new per-space signals (summary, summary_on) are registered in held!. If they were dropped from it, a summary open in one review would appear in the next.

Which guide opens. summary::home takes the first change page the PR itself touches. A PR that edits another branch's guide as well could open on the wrong one; a PR without a guide opens on the map's root.

Not changed

The app never writes .pullspace/: pages come only from the agent skills, and writing to GitHub is still a README plan. The HTML Preview keeps its empty sandbox. blobs::VERSION is not bumped (see Decisions). CI is untouched: the skills' shell scripts have no tests in it, and check.sh is run by the agents, not by CI. The browser extension is untouched.

How it was checked

  • cargo test: 322 passing. New tests in backend/summary.rs cover path mapping, children, stamp parsing, freshness, drift, the root stamp (checked against real git mktree output), link resolution, the frame document, and the other side not breaking out of the script. A tree-parsing test in github.rs covers directory hashes and the root stamp.
  • cargo clippy -- -D warnings, cargo fmt --check, and cargo check --target wasm32-unknown-unknown in debug and release: clean.
  • The sandboxed frame was probed in headless Chrome and in WebKit (WKWebView). Page scripts, on… handlers and remote images are blocked. Only real link clicks reach the app, spoofed postMessages are ignored, the frame's document is opaque to the parent, and the theme applies.
  • The real App was mounted headlessly (in a scratch copy, not in the repo) and walked through welcome → guide → before/after → root → a stale page → following a link out and back → closing, with SSR screenshots.
  • The skills were dogfooded by sub-agents writing this repository's own map, and this guide was written with pullspace-change. check.sh is clean and plan.sh reports every page current.
  • Not verified: clicking through in a real browser against live GitHub. Nobody has yet opened a real PR with summaries in pullspace, so the GitHub tree's modes and the root stamp have only been checked against fixtures and local git.
