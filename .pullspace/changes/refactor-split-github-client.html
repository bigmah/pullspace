Split the GitHub client into a module per concern

This moves the 4,800-line backend/github.rs into backend/github/, one file per area of the API, without changing any behaviour or any path outside the module.

Why

github.rs held search, owners, branches, pull requests, file lists, snapshots, comments, commits, compares, CI checks, the GraphQL read, time formatting, file reads and FetchJob, plus 1,200 lines of tests. Finding the code for one endpoint meant scrolling past a dozen others. FetchJob even sat below the test module. It was the fourth most-changed file in the repository.

Reading order

  1. mod.rs: the module list and re-exports. Start here. Lines 1–68 are the old file's header, uses and constants, unchanged. Every submodule is pub used, so github::X still resolves for every caller. Children see the constants because a child module can read its parent's private items.
  2. request.rs: the shared plumbing (path encoding, get_raw, refused, get_json, rate-limit messages, the User model). Each other file starts with use super::*; and gets these from here.
  3. pulls.rs: RawCompare: the one kind of real edit in the move. Items that were private are now pub(super). So are the fields of the raw wire structs that a sibling file or the tests read (RawPr, RawCompare, RawCommit, RawRef, RawRefRepo, RawRepo, User, and the three commit structs the tests construct).
  4. snapshot.rs: snapshot_of: the only path that had to change. super::summary is now crate::backend::summary, because super is one level deeper. Three doc links got the same fix.
  5. tests.rs: the old test module moved whole and de-indented one level. Some JSON fixtures are multi-line raw strings, so their inner whitespace shifted. JSON ignores that, and every test still passes.
  6. The rest (target.rs, find.rs, repo.rs, conversation.rs, commits.rs, checks.rs, time.rs, more.rs, fetch.rs) is text moved verbatim, then run through cargo fmt. git diff -M won't pair them with the old file, so compare the moved blocks by eye, or skim them.

Decisions

Glob re-exports from mod.rs, not updated call sites. Callers across ui/ and backend/ write github::X. Re-exporting keeps this PR to one directory. The cost is that github::X doesn't say which file X is in. The src/backend/ page now lists the files.

pub(super) fields on the wire structs, not moving each struct next to its only reader. RawCompare and RawRef each have readers in two files, so there is no single right home for them. The fields stay invisible outside backend::github.

One tests.rs, not tests split across the files. Sorting 1,200 lines of tests by what they cover is a separate change, and mixing it in here would make this one harder to check as a pure move.

Section boundaries from the old file. The splits follow its // ---- section headers, except where a section had outgrown its name. "Finding an account" ran on through branches, PRs and snapshots, and became find, repo, pulls and snapshot.

Risks

If a block was dropped or duplicated in the move, it would show up as a compile error or a missing item. The split script checked that every non-blank line of the old file landed in some new file, and the line ranges it cut don't overlap.

Glob re-exports can shadow each other. Two submodules exporting the same name would make github::X ambiguous, and that is a compile error, so it can't slip through silently. None exist today.

Not changed

No logic, no signatures, no public names, no dependencies. ui/github.rs is a different module (the GitHub panel) and is untouched. The old guide feat-summaries.html still links to line numbers in github.rs. That page describes its own PR's head, so its links are left as they were.

How it was checked

  • cargo test: 322 passed, the same count as on main.
  • cargo clippy --all-targets: no warnings.
  • cargo check --target wasm32-unknown-unknown --release: builds.
  • cargo doc: no new warnings. The redundant-link warning on mod.rs line 5 was already there in github.rs.
  • The app itself wasn't run. Nothing a browser does differently could change: the moved code compiles to the same items.
