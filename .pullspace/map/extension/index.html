extension

A Manifest V3 Chrome extension that hands the github.com page you are reading to pullspace, as a single escaped ?url= field, in the pullspace tab you already have open if there is one.

How it works

Three entry points, one action. The toolbar button, the Alt+Shift+P shortcut (the manifest's _execute_action command) and two right-click items all end in open(target, tab) in the service worker. It reads the configured base from chrome.storage.sync, builds the address with handoffUrl, and then picks a tab:

  1. A pullspace tab that is already open, chosen by pullspaceTab: one in the clicking window first, then the most recently viewed. It is navigated to the new URL and focused. If the target is not GitHub, the tab is only focused, so it keeps what it had open.
  2. Otherwise a new tab right beside the source tab, with openerTabId set so closing it returns to GitHub. With the new tab option off, the current tab is navigated instead.

The whole contract with the app is that one query field. The field, not the fragment, because GitHub already puts #L58 in the fragment and a URL only has one; searchParams form-encodes it, and param in route.rs decodes exactly that. The app reads it in take_handoff, removes it from the address bar, and puts the link into its own space with make_room. That is why reusing one tab loses nothing that was open there.

Everything that decides the URL lives in handoff.js, which uses no chrome.* API so that node --test can run it directly (test.js). background.js and options.js are thin glue around it.

Permissions, and why each is there

activeTab puts url on the tab object, but only at the moment the extension is invoked. There is no content script and no page access. addressOf falls back to tabs.query for paths that hand over a tab without a URL. Finding an existing pullspace tab needs its address, and Chrome only shows tab addresses on granted hosts. So host_permissions covers https://pullspace.dev/* (the default), and optional_host_permissions lets the options page request the host of a self-hosted copy (options.js). If that request is refused, the extension still works, but every click opens a new tab.

Invariants

  • The escaping must be what route.rs decodes. The test "the escaping is what route.rs undoes" and what_a_browser_escapes_is_what_this_reads_back in Rust are the two halves of one contract. A change to either one should show up in both.
  • DEFAULT_BASE and host_permissions move together (handoff.js, manifest.json). If the default host is not granted, a fresh install can't see an open pullspace tab, so every click opens a new one.
  • Only github.com is handed over. The regex is anchored to the host, so notgithub.com, github.com.evil.test and gist.github.com are all refused. Anything else goes to the bare base (the front page) with no ?url=.
  • A pullspace tab is matched by origin and page path, not by host alone (isPullspace). …/ and …/index.html count as the same page, and so does any # route. A copy in a subdirectory doesn't claim the rest of its host.
  • Plain http is only assumed for this machine (localhost, 127.0.0.1, [::1]). Any other bare host gets https. localhost.evil.test is not treated as local.

Gotchas

Register listeners at the top level of background.js. An MV3 service worker is stopped when it is idle and restarted by the next event. A listener added inside a callback exists only in the run that reached that callback (the file's own header).

Context menus are created in onInstalled, not on wake-up. Chrome stores them, and creating a menu that already exists is an error. removeAll runs first so that renaming one in an update is safe (background.js).

The permission request in options.js is made before any await. Chrome only shows a permission prompt for a request made while handling the user's click. Moving it after the storage write would silently deny it (options.js).

An old deployment looks exactly like a broken extension. A pullspace build from before take_handoff existed leaves ?url= in the address bar and shows the front page. The fix is to redeploy the app (README).

New files need adding to make.sh's exclusions if they are dev-only. make.sh ships everything except a fixed list (make.sh), so a new dev-only file goes into the zip unless you exclude it. Bump "version" in the manifest for each store upload.

The Rust side of the contract has two tests. what_a_browser_escapes_is_what_this_reads_back holds strings produced by this extension's URLSearchParams: a space as +, a literal plus as %2B, and & and = escaped. a_handed_over_url_is_read_out_of_the_query follows one handoff through param and github_link. test.js's header names only the second one, and the README names only the first.
