pullspace

An IDE-style GitHub code reviewer that is a static page: Rust compiled to wasm, calling api.github.com straight from the browser tab, with no server anywhere and the code never leaving the browser.

Where to start

  1. src/main.rs: thirteen lines, and its doc comment is the whole deployment model.
  2. src/: how the crate splits into ui and backend, and one review traced end to end.
  3. src/ui/: the St signal store, workspaces and spaces. Most changes land here, and most of the traps (unregistered per-space signals, peek() across a write) are here.
  4. src/backend/: the GitHub client, the clone into OPFS keyed by blob SHA, and where untrusted content is made safe.

Then, as needed: extension/ (the Chrome extension's ?url= hand-off) and skills/ (the agent skills that write these summary pages).

How it works

dx build --platform web --release turns the crate into an index.html, a .wasm and a .js; any static host serves them (main.rs, Cargo.toml). The app reads pull requests, commits, branches and compares over GitHub's REST API from the tab, clones each commit's files into the browser's Origin Private File System under their git blob SHA, and gives them an explorer, a diffing code viewer, search and Go to Definition. Several reviews ("spaces") can be open in one tab. Signing in is optional: a pasted token, kept in localStorage, is needed only for private repositories and higher rate limits.

Two consequences shape the whole codebase. First, the token shares an origin with every untrusted file shown, so repository content never becomes markup in the app's document: Markdown is parsed into the app's own elements, and HTML only renders in sandboxed frames (details on the src page). Second, a panic in wasm stops the tab, so the known panic traps (std::time, byte-slicing &str, peek() held across a write, unbounded recursion on untrusted input) are treated as bugs on sight.

The .pullspace/ summaries

These pages are a pullspace feature. A repository can commit a .pullspace/ directory holding a map (one static HTML page per important directory) and per-PR change pages. pullspace shows the page beside the code, walks the tree through its links, and marks a page current or out of date by comparing the git tree hash stamped in it with the directory's hash in the snapshot. On a PR that rewrote a page, it shows the page before and after, side by side, with the passages only one side has lit. SUMMARIES.md is the user-facing account of the feature. The root is stamped with its tree minus .pullspace/, so writing a page doesn't outdate the root. Pages are written by a coding agent following the skills in skills/, steered by .pullspace/seed.md; the app only reads them (backend::summary for paths, stamps and the sandboxed frame document, ui::summary for the pane). They render in a sandboxed frame with no network, styled by assets/summary.css, which follows the app's theme.

Building, checking, shipping

The toolchain is pinned exactly (rust-toolchain.toml, with the wasm target) because CI denies clippy warnings, and a floating channel would turn a green repository red when a new lint ships. CI runs cargo fmt --check, clippy with -D warnings, host cargo test, cargo check --target wasm32-unknown-unknown (the target that ships, which the tests never build), and the extension's node --test. deploy/Caddyfile is a worked self-hosting config whose comments explain its four load-bearing parts: immutable caching for hashed assets, no-cache on index.html, a connect-src CSP that confines the token to GitHub's two hosts, and HTTPS, without which the browser withholds OPFS and the local copy silently degrades.

What's in here

src/
The app: backend (GitHub, clone, blob store, parsing) and ui (Dioxus components over one signal store).
extension/
Manifest V3 Chrome extension that hands the github.com page you are on to pullspace as a ?url= field, reusing an open pullspace tab.
skills/
The agent skills that write .pullspace/ pages: the format contract, stamp/plan/check scripts, and templates. .claude/skills symlinks here.
assets/style.css
The app's stylesheet, compiled in with include_str! (app/mod.rs); its :root variables are the theme defaults that backend::prefs overrides.
assets/summary.css
The stylesheet handed to summary pages in their frame (summary.rs); it defines the class vocabulary pages are written in.
index.html
The page template dx fills in. It carries the tab icon, percent-encoded, because Safari only reads an icon from the page as served, before the wasm runs.
Cargo.toml
Dependencies, each commented with why it is there (notably similar's wasm32_web_time and web-time, both to avoid std::time panics; sha1_smol for the root summary stamp). The dead server-dev/android-dev profiles are rewritten by dx on every build, so they stay.
Dioxus.toml
The app name and title for dx, and a commented-out base_path for a GitHub Pages project site.
rust-toolchain.toml
Exact toolchain 1.93.0 with rustfmt, clippy and the wasm target.
.github/workflows/ci.yml
Format, clippy, host tests, the wasm check, the extension tests.
deploy/Caddyfile
Self-hosting on Caddy, with the reasons for each header.
demo/preview.html
A hostile fixture for the HTML Preview: open it in pullspace and everything in it that tries to run or load is inert.
README.md
The pitch, features, plans, and the build command. diff.png is its screenshot.
SUMMARIES.md
Summaries for users: what the map and the guides are, installing the two skills, reading pages in pullspace, and the scripts.

Invariants

  • No server. Anything that sounds like it needs one is done in the tab. The deployment is a directory of static files (Caddyfile).
  • The token only goes to GitHub. The code sends it nowhere else, and the Caddyfile's connect-src makes the browser enforce it on a self-hosted copy.
  • CI must stay green on the wasm target, not just the host. cargo test never builds wasm, so the separate wasm check is what catches a wasm-only break.
  • The extension's escaping and backend::route's decoding are one contract, pinned by a test on each side; CI runs both (ci.yml).

Gotchas

Plain http hides a broken cache. OPFS is only given to a secure context, and localhost counts as one, so a copy served over plain http elsewhere quietly falls back to memory and nobody sees it in development (Caddyfile).

A cached index.html ships an update nobody receives. It is the one file that names the new hashed .wasm/.js (Caddyfile).

Bumping rust-toolchain.toml is a deliberate commit: fix whatever the new clippy flags in the same change, or CI goes red.
