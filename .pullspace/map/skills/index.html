skills

The coding-agent half of pullspace's summaries: two agent skills, with the format contract, scripts and templates they share, that write the .pullspace/ pages the app shows beside the code.

How it works

pullspace only reads summaries. It never writes them. Pages are written by a coding agent following one of these skills and are committed to the repository like any other file. The reading half of the contract is src/backend/summary.rs (paths, stamps, the sandboxed frame) and src/ui/summary.rs (the pane). This directory is the writing half. .claude/skills holds symlinks back here, so Claude Code picks the skills up from the repository.

  • pullspace-map builds or refreshes .pullspace/map/, one page per directory that matters. It reads seed.md for steering (creating it from a template if it is missing), runs plan.sh to see which pages are current, stale, unstamped or orphaned, writes pages bottom-up so each parent summarizes its children's pages rather than their source, stamps each page, and runs check.sh.
  • pullspace-change runs before a PR is opened. It writes .pullspace/changes/<branch>.html (why, a line-anchored reading order, decisions, risks, what was checked) and rewrites or restamps the map pages that affected.sh names as nearest to the changed files, leaving pages that are only ancestors alone. It has no files of its own beyond SKILL.md, and uses pullspace-map's FORMAT.md, scripts and change.html template through <map>/ paths, <map> being the sibling pullspace-map/ directory.

The stamp is git's tree hash

Freshness needs no state outside the repository. A map page records git rev-parse <tree>:<dir> for the directory it describes, and that hash changes exactly when something under the directory does. The root is the special case: its tree contains .pullspace/, so writing any page would make the root page stale. The root is therefore stamped with a tree rebuilt without that entry (stamp.sh, git mktree), and the app rebuilds it the same way in root_stamp.

stamp.sh and plan.sh take --worktree (the default), --index or --head; affected.sh reads page states from plan.sh in its default mode. Worktree mode copies the real index to a temp file, runs git add -A into it under GIT_INDEX_FILE, and calls write-tree (stamp.sh). That lets it hash untracked, not-ignored files without touching the user's staging area. With --write, stamp.sh also writes the stamp and today's date into the directory's page, replacing the two tags already there.

What's in here

pullspace-map/SKILL.md
The map workflow: seed, plan, write bottom-up, stamp, check.
pullspace-map/FORMAT.md
The contract: layout, stamp syntax, sandbox rules, link rules, section order, and the CSS class vocabulary pullspace styles.
scripts/stamp.sh
Prints a directory's tree hash ("" for the root, without .pullspace).
scripts/plan.sh
Tab-separated status: each page current/stale/unstamped/orphan, then each directory without a page with its file counts (total and direct).
scripts/affected.sh
For a base commit, which pages the changed files fall under: for each, how many changed files it is the nearest page to, how many are under it, and its state; then changed directories only the root covers.
scripts/check.sh
A grep-based lint over each page's tags: title, lede, stamp, nothing the sandbox refuses, every link /-rooted and present in the working tree, and every #L anchor inside its file.
templates/
Skeletons for dir.html, change.html and seed.md.
pullspace-change/SKILL.md
The per-PR workflow: find the diff against the merge base, update the affected map pages, write the guide.

Invariants

  • The stamp is written exactly as FORMAT.md shows: double quotes, name before content, 40 lowercase hex characters. The app's parser accepts any attribute order or quoting (summary.rs), but plan.sh and check.sh use a literal sed/grep pattern (check.sh, plan.sh). A variant the app accepts will show as unstamped to the scripts.
  • The root stamp must leave out .pullspace in the scripts and the app alike. If stamp.sh and root_stamp ever disagree, the root page will always show as out of date. plan.sh repeats the same awk | git mktree line rather than calling stamp.sh.
  • Pages are the sandbox's input, so they have no scripts, event handlers, external resources or CSS of their own. The app draws them in a sandboxed, opaque-origin frame that must never reach the GitHub token (seed.md's security boundary). check.sh enforces this. The rule is not cosmetic.
  • A current stamp is a promise. pullspace-map forbids restamping a page nobody re-verified (SKILL.md). pullspace-change also says to leave ancestors alone while their text is still true, because restamping them would conflict with every other open PR (pullspace-change).
  • Keep the section order fixed (how, parts, invariants, gotchas, plans). pullspace shows a rewritten page before and after, side by side, and that comparison only works when the structure holds still.

Gotchas

Editing anything here makes this page stale. These pages are stamped like any other directory, so a change to a skill's wording moves the tree hash of skills.

check.sh lints tags, not parsed HTML, and cannot tell a right line from a wrong one. It pulls every <…> tag out with a regex and checks only those (check.sh), so markup shown escaped inside <pre><code> is fine. A #L anchor passes as long as the file is that long: when code moves, an anchor that now points at the wrong lines is not reported, and has to be re-checked by hand.

Worktree stamps include uncommitted and untracked files. A page stamped this way is only current if the commit contains exactly what was on disk. If the code is already committed and the tree has unrelated edits, use --head. The same goes for plan.sh's default mode.

pullspace-change's <map> is a placeholder, not a path. It stands for the sibling pullspace-map/ of wherever the skill is installed (skills/ here, .claude/skills/ in a repository that copied them), and is defined once near the top (SKILL.md). Its command blocks use it without repeating that.
