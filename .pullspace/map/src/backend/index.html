src/backend

Everything pullspace does that isn't drawing: talking to GitHub from the browser tab, keeping a repository's files on disk by git hash, and turning untrusted files into data the UI can show safely.

How it works

There is no server. The only way out of the tab is http.rs, a thin wrapper over the browser's fetch that hands back the status, the body and the rate-limit headers, and never treats a status as an error on its own (a 404 is "the base side of an added file"). github/ sits on top: a REST (plus one GraphQL read) client for pull requests, commits, compares, branches, comments and checks, one file per area. Every request goes through get_raw and refused, which turn 401/403/429 and an empty rate budget into readable errors that name which budget ran out, because the one people exhaust (search) says nothing about the others. The four writes (writes.rs: a discussion comment, a reply to a line thread, a single line comment, and a review with its line comments) are each one JSON POST through post_json, which refuses to go out without a token and turns a refusal into GitHub's own words with write_error: "Can not approve your own pull request" is something the reader can act on, and the status alone is not. Nothing outside http.rs is browser-specific, which is what keeps the parsing testable with plain cargo test.

Opening a workspace starts with a snapshot: repo_tree reads the commit's whole tree in one request into a Snapshot (sorted file list with blob SHAs, plus every directory's tree hash). Then clone::hydrate pulls the commit down: plan works out which blobs are missing, putting the PR's changed files first, and fetch gets them twelve at a time. It tries raw.githubusercontent.com first (unmetered, CORS-open, no token), and falls back to the API's blob endpoint when the CDN 404s, meaning the repo is private. Budgets cap what one clone may take: 1 MB per file, 96 MB and 20k files per commit, 1,500 API calls. The comment at the top of clone.rs explains why this can't be a real git clone: GitHub's smart-HTTP and codeload endpoints refuse cross-origin callers.

The bytes land in blobs.rs, a content-addressed store on top of opfs.rs (the browser's Origin Private File System): blob/<xx>/<sha> for contents and snap/<owner>~<name>~<commit>.json for the snapshot. Because blobs are keyed by git's hash, a second PR on the same repository only downloads the files that actually differ. Reads go through read_pair/read_bytes: disk if present, network if not, and cached on the way past. A reader waiting on a file holds a Waiting guard, and the clone stands aside until it drops, because OPFS serves requests in order and a single read would otherwise sit behind thousands of writes. sweep drops the least recently opened repositories (the manifest's mtime) once the store passes 1 GB.

Everything above the store is plain data work: scan.rs walks a snapshot back out of the store (with a 48 MB decoded-text cache that stays valid across PRs because it is also keyed by content), and feeds search.rs and symbols.rs. difftool.rs diffs two FileContent sides, highlight.rs colours them, and tree.rs builds the explorer's file tree. Small modules persist settings in localStorage through store.rs.

Where the security lines are drawn. The token lives in localStorage (auth.rs, whose header explains why pasting a token is the only sign-in a static page can offer), and its Debug impl is redacted. Untrusted content is handled three ways. markdown.rs parses Markdown into its own block/span tree and never emits HTML; raw HTML is dropped except <details>, <summary>, <br>, <img> and comments, which are read into nodes. images.rs inlines repository images as data: URLs and deliberately never loads off-site images, since a request from a tab that holds a token would tell the host who read the PR. HTML pages, the summaries included, only render in a sandboxed frame: summary::frame_doc wraps the page in a CSP that blocks the network and every script except its own nonce'd one, and strips <meta http-equiv=refresh>, which no CSP can stop. That one script is the link bridge, plus, on a page a PR rewrote, the before/after comparison; the other side of the page rides inside it as a string, escaped by script_string so that nothing in it can close the script early.

summary.rs is the reading half of the .pullspace/ format: path mapping between directories and pages, meta (a scan of the stamp, not an HTML parse), freshness (the stamp compared with Snapshot::dir_sha), drift, and resolve for links. The frame's script is two pieces of JavaScript kept here as constants: BRIDGE_JS posts a clicked link up to the app and scrolls an in-page #anchor itself (a srcdoc document's base URL is the app's, so the browser would load the app into the frame), and COMPARE_JS parses the other side of a rewritten page with DOMParser and marks each innermost passage (paragraph, list item, heading) whose text the other side lacks, with ps-new or ps-gone according to Against. The root's stamp is a tree GitHub never saw, so root_stamp rebuilds it byte for byte from the root entries without .pullspace, and snapshot_of only does that for an untruncated tree.

What's in here

mod.rs
FileContent (Text / Binary / Absent), git's NUL-byte binary test, and breathe, which yields to the event loop with a timer.
http.rs
GET and POST over fetch; returns status and rate-limit headers, never judges them.
github/
The GitHub client and its models, one file per area: request.rs (headers, errors, rate limits), target.rs (parsing owner/repo and links), find.rs and repo.rs (repositories, owners, branches), pulls.rs, snapshot.rs, conversation.rs (comments, with the id, thread root and side a reply or an in-diff thread needs), writes.rs (comment, reply, line comment, review), commits.rs (commits and compares), checks.rs, time.rs, more.rs (the pr_more GraphQL read) and fetch.rs (FetchJob and file reads). mod.rs re-exports all of it, so callers write github::X whichever file X is in.
clone.rs
Hydrates a commit into the store (CDN first, API for private repositories) and reads file pairs back.
blobs.rs
Content-addressed blob and snapshot store, with its version marker, the 1 GB sweep, and clear.
opfs.rs
Best-effort OPFS primitives: dir, read, write, list, remove, usage, persist.
scan.rs
Walks a snapshot's text files out of the store, with a decoded-text cache; reports what it couldn't read.
search.rs
Pure matching: case, whole-word and regex toggles compiled into one Regex; also Find References.
symbols.rs
ctags-style, one regex per line per language definition index; indentation stands in for nesting.
fuzzy.rs
Greedy subsequence scoring for the file picker (word starts, runs, basename bonus).
difftool.rs
Line diff with word emphasis, whitespace folding, context gaps and expansion, split-view rows, and the overview ruler.
highlight.rs
syntect highlighting; the light/dark choice is a global atomic, not a signal.
tree.rs
ChangeKind and the explorer's FileNode tree: building, visible rows, filtering and search.
markdown.rs
Markdown into the app's own block/span tree, never HTML; outline and README detection.
images.rs
Repository images as data: URLs; src/srcset scanning and rewriting for previewed HTML.
summary.rs
Reads .pullspace/ pages: paths, stamps, freshness, drift, link resolution, and the sandboxed frame document with its link bridge and before/after marking.
route.rs
The #/owner/repo/… fragment routes, github.com link parsing, and the ?url= handoff from the extension.
auth.rs
The pasted token, and opening tabs.
store.rs
Prefixed localStorage keys, plus sessionStorage for the per-window set of spaces.
prefs.rs
Theme, accent, fonts and spacing, emitted as a :root CSS-variable block by Prefs::css.
layout.rs
Pane sizes, clamped back into range on load.
drafts.rs
A review being written: held line comments and the summary, per pull request in localStorage, read-modify-written whole so two windows do not overwrite each other.
viewed.rs
"Viewed" marks, stored by blob hash so they survive a force-push that doesn't touch the file.
crash.rs
The crash screen, installed as page script so that it still works after the wasm module traps.
clip.rs, screen.rs
Clipboard write and fullscreen, both of which have to be called on the user's gesture.

Invariants

  • Storage is best effort and never fatal. OPFS, localStorage and sessionStorage can all be missing, full or refused. Every function in opfs, blobs and store returns None/false, and callers fall back to the network. A cache miss must cost speed, never correctness.
  • Blob files are named only by a 40-hex SHA (is_sha), and a read checks the length the tree promised. Nothing here computes SHA-1, so that length check is the only integrity check there is.
  • Bump VERSION whenever the on-disk format or the write path changes. Bumping it wipes the store on the next load. It exists because pre-0.2 writes could be silently zero-filled, and a file of zeros looks just like a real binary file.
  • A snapshot's files and dirs stay sorted by path, because entry and dir_sha are binary searches. The root's entry in dirs is the tree without .pullspace, and it is left out when the tree is truncated, since a wrong stamp is worse than none.
  • Only http.rs touches the browser's network, and nothing in github/, search, symbols, difftool, markdown or summary needs a window. Keep it that way, or those modules lose their host tests.
  • Untrusted text never becomes markup in the app's document. Markdown becomes nodes, the crash screen uses textContent, and HTML only ever renders inside the sandboxed frame from frame_doc.

Gotchas

Panics kill the tab. wasm doesn't unwind, and crash.rs can only paint a screen afterwards. The traps that recur here: std::time::SystemTime panics in a page, so use web_time as seconds_until does; byte-slicing &str off a char boundary (find_ci only works because every needle is ASCII); and unbounded recursion on untrusted input, which is why MAX_NEST caps Markdown nesting at 64.

Don't pass a &[u8] straight to a JS write. opfs::write copies onto the JS heap on purpose: a view into wasm memory can be detached by any later allocation before the browser reads it. That is the zero-filled-blob bug the store's version marker exists for.

Don't send Authorization to the CDN. RAW gets no auth header, because a header makes the request preflighted and the CDN doesn't answer preflights. Private repositories go through the API instead, and clone remembers which repositories the CDN refused.

Clipboard and fullscreen must run inside the click. An await between the gesture and clip::copy or screen::enter uses up the user gesture, and the browser then refuses.

The syntax theme is a global, not a signal. use_light must be set before the signal that triggers the redraw, or the colours and the palette they sit on will disagree.

A 404 from a write is a permission, not a missing pull request. A token that can read a repository but not write to it gets 404 from the write endpoints, because GitHub will not confirm what it will not let you touch. write_error says so; don't route writes through get_json's "Not found, check the name" message.

Two storages with different lifetimes. SPACES lives in sessionStorage (per window) and everything else in localStorage (per origin). Putting spaces in localStorage would have two windows fighting over one key.
