src

The whole app: one Rust crate, compiled to wasm, that is the code reviewer in the browser tab, with nothing behind it but api.github.com.

How it works

The crate is split in two, and the split is the thing to hold on to. backend is everything that isn't drawing: the GitHub client, the clone into the browser's file system, the content-addressed blob store, diffing, highlighting, search, and the parsers that turn untrusted files into data. ui is the Dioxus app: one store of signals (St) and the components that read and write it. ui calls into backend; backend never calls back (its only mention of ui is a doc link in store.rs).

main.rs is the whole entry point: it launches ui::App and then installs the crash screen (crash::catch). Its doc comment is the deployment story: dx build --platform web leaves an index.html, a .wasm and a .js, any static host serves them, and "that is the whole deployment".

A review, end to end: an address (typed, linked, or handed over by the extension) becomes a Route; ui's loaders fetch a snapshot of the commit through backend::github and land it with St::enter; an effect starts backend::clone, which pulls every blob into OPFS under its git SHA (backend::blobs), so a second PR on the same repository only downloads what differs; the viewer then decodes only the files somebody opens, and search and Go to Definition read the rest back off disk. Several such workspaces ("spaces") share one tab by swapping every per-space signal in and out of St (ui::spaces).

The security boundary is drawn across both halves. The GitHub token sits in localStorage (backend::auth) in the same origin as every file shown, so nothing from a repository becomes markup in the app's document. Markdown is parsed into a tree by backend::markdown and built into elements by ui::markdown. HTML only renders in a sandboxed frame without allow-same-origin: an empty sandbox for a file's Preview (viewer::render_preview), and for .pullspace/ summaries a CSP-wrapped document from backend::summary::frame_doc, shown by ui::summary::frame, whose one script is nonce'd: a link bridge, plus the before/after marking on a page a PR rewrote. Off-site images are never loaded (backend::images).

What's in here

main.rs
Launches ui::App, then installs the crash screen. Order is deliberate; the reason is in crash::catch.
backend/
Transport, clone, blob store, and pure data work (diff, highlight, search, symbols, markdown, summaries). Everything testable with plain cargo test.
ui/
The Dioxus components, the St signal store, workspaces and spaces, routing, and the sandboxed frames.

Invariants

  • backend doesn't depend on ui, and only http.rs touches the network. That is what lets the diff, markdown, search, symbol and summary code run under host cargo test in CI. Browser calls leaking into those modules cost their tests.
  • Repository content never becomes markup in the app's document. Each half holds one side of this: backend never emits HTML from Markdown and builds the frame document; ui builds elements from the tree and never grants a frame allow-same-origin.
  • Every per-space signal is registered in held!. A signal added to St without it leaks from one review into the next.
  • Storage failures are never fatal. OPFS and both web storages may be missing or full; a miss costs speed, not correctness (see backend).

Gotchas

A panic ends the tab. wasm doesn't unwind; crash.rs can only paint a screen with the file and line afterwards. The recurring traps on both sides: std::time::Instant/SystemTime (use web_time), byte-slicing a &str off a char boundary, unbounded recursion on untrusted input (Markdown nesting is capped), and in ui, a signal's peek() held across a call that writes the same signal (bump_tick shows the safe form).

cargo test passing says nothing about the wasm build. Tests build for the host. Check cargo check --target wasm32-unknown-unknown too, as CI does.
