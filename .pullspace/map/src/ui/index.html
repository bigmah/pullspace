src/ui

The whole visible app: the Dioxus components that draw the explorer, code viewer, conversation and pickers, and the one signal store (St) that every one of them reads and writes.

How it works

One store, in the root scope. App builds St, a Copy struct of about eighty signals, and provides it as context; every component starts with use_context::<St>(). Each signal is made with root(), i.e. owned by ScopeId::ROOT rather than by App. The comment there gives the reason: fetches are started with spawn_forever (which runs in the root scope) so they outlive the row or panel that started them, and a signal owned by App (three scopes down, under Dioxus's error and suspense boundaries) would be written from outside its scope on every fetch.

What is open is a Workspace: Empty, Pr, Repo (a branch), Commit or Compare. Each non-empty variant carries a Snapshot (path → blob SHA) of its head and, except Repo, of its base. A pull request is treated as a repository with some files marked changed (St::statuses), so the explorer and viewer barely care which variant they have. St::enter is the single place a new workspace lands: it decides what survives (the conversation survives stepping into one of the PR's commits, branches survive anything in the same repo, checks do not), writes the workspace, then writes the address bar via route::show. Order matters there; see Gotchas.

Getting there. Everything that opens something goes through a Route: nav.rs follows the address bar (initial link, Back/Forward, hashchange), github::open_route dispatches to open_pr / browse_repo / open_compare / …, and those fetch from GitHub (via backend::github) and finally call St::enter_*. While a space is on its way, St::incoming holds the route and opening.rs is drawn instead of the landing page.

Getting the files. As soon as a workspace is written, an effect in App spawns prcache::clone_repo, which pulls the whole tree into OPFS keyed by blob SHA (backend::clone, backend::blobs); that is why a second PR on the same repo is nearly free. A second effect then runs ide::build_index over the same files for Go to Definition. The UI only ever decodes the files somebody looks at: prcache keeps up to 128 decoded base/head pairs in St::pr_files (LRU), and imgcache does the same for pictures as data: URLs, bounded at 24 MB. Both are the only writers of their signals.

Spaces. Several workspaces can be open in one browser tab. There are not several Sts: spaces.rs declares every per-space signal once in the held! macro, which generates Held and Held::swap, a mem::replace of each signal's contents. spaces::go_to stows the reading position, swaps, and retires work in flight. Two things are not signals and are handled separately: scroll offsets live in a JS object in the page, keyed by space (tabs.rs), and in-flight fetches hold a Claim and drop their result if the space on screen has changed. The space list is saved to session storage as links only, and a restored space is refetched on first visit.

Untrusted content, three ways. A GitHub token sits in localStorage beside every file shown, so nothing from a repository reaches the page as markup:

  • Markdown (READMEs, PR descriptions, comments) is parsed by backend::markdown and built into the app's own elements by markdown.rs. Images are fetched only out of the repository being read (backend::images).
  • An HTML file's Preview goes into an iframe with sandbox="" (everything denied, no same-origin): viewer::render_preview. A summary page is the exception: asked for in Preview, or clicked in the explorer, it goes to the summary pane instead, whose frame lets links through.
  • A .pullspace/ summary page goes into an iframe with sandbox="allow-scripts" and no allow-same-origin (summary::frame). The only script allowed in is the one backend::summary::frame_doc injects under a per-load nonce: the link bridge, which posts clicked links out signed with a random token, and, on a page the PR rewrote, the comparison that lights passages only one side has. side_of hands each side the other's text for that, and only when both sides exist. LISTEN_JS accepts a message only if the token matches and its source is one of the iframe.summaryframe windows, then follow opens the directory's page, the file at its line, or the browser.

Page-side listeners. Things that fire too often for a Rust handler per element (hover over tree rows, clicks on line numbers, the + that starts a line comment, scroll positions, the keyboard, fullscreen changes, summary links) are one document::eval snippet each, installed once from App via use_future, sending back over dioxus.send. Each snippet removes its previous listener first, so a reload of the script does not stack them.

Writing back. review.rs is everything that sends something to GitHub. A line comment is written in the diff: the viewer asks review::talk (inside a memo, so typing the review's summary does not redraw the diff) which lines have something under them, and Talk puts a + on every line GitHub's own diff has (anything not inside a contracted gap, since GitHub refuses the rest) and draws LineThread under the lines that need one: existing threads with a reply box, held notes, and the box being written in. By default a note is held, in backend::drafts, and ReviewBox at the foot of the conversation sends them all with the verdict as one review. Replies and "Comment now" go at once. Three signals carry it, all global and keyed by pull request rather than per space: drafts, composing (the one open box) and writing (the one write in flight, or the one that failed, tagged with the box it came from). After a write, conversation::reload refetches without putting Loading up, so nothing on screen blinks.

Invariants

  • Every per-space signal is in held!, and App seeds it from h (Held::fresh()). A field added to St but not to held! leaks from one review into the next. The comment there notes that this cannot be noticed "except by using the app for a week". Signals that are deliberately global (theme, pane sizes, read_wide, top_line, the picker, the token, space itself, and the review state, which is keyed by pull request instead) are the ones App seeds with a literal instead of h.*.
  • Every signal is created with root(), including ones added later. Anything written from a spawn_forever task must be root-owned.
  • A fetch takes its Claim before its first await, and checks claim.kept() before landing. A claim taken after a wait claims whichever space the wait ended in. The generation counter (St::generation, bumped by enter) is a separate guard, meaning "superseded", used by the clone and index tasks.
  • Repository content never becomes markup. Markdown goes through the parser and element builder; HTML only ever renders in a sandboxed frame; neither frame gets allow-same-origin. See backend::markdown and backend::summary for the other half of those lines.
  • No std::time::Instant: it panics on wasm32-unknown-unknown. Use web_time::Instant (see panes.rs) and compat::sleep. Duration is fine.

Gotchas

peek() held across a call. The code habitually binds a signal read to a local (let v = *tick.peek(); tick.set(v + 1);, see bump_tick). Writing tick.set(*tick.peek() + 1) or passing &*sig.peek() into a function that writes the same signal keeps the borrow alive and panics. In wasm a panic ends the tab. Treat those locals as load-bearing, not as style.

A keyed component must not move what its key reads. Row { key: "{c.id}", c } passes a debug build and fails --release ("borrow of moved value"): the macro formats the key after the props have taken the value in one and not the other. Keep the clone (c: c.clone(), as in LineThread), and run cargo check --target wasm32-unknown-unknown --release on any rsx change with a key.

St::enter writes the workspace before the address bar. Writing the bar raises hashchange, and nav::watch tells our own writes from Back/Forward by asking what is already open. Reordering these makes every open look like a navigation.

"Set, never cleared" signals. scroll_to and anchor are requests: effects fire on each write, and the value left behind means nothing. Clearing one from its own effect is a write to a subscribed signal, which Dioxus reports as a loop. To tell "opened at a line" from "opened", read at_line.

Effects in App re-run when you switch back to a space, because the swap writes workspace. The clone and index effects therefore check "already finished / already Ready" before spawning anything. A new workspace-driven effect needs the same guard, or every space switch redoes the work.

Summary pages ride the file cache. SummaryPane reads its page through prcache::ensure_path and St::pr_files like any other file, both sides on a PR. The "what moved since" check is one GitHub request for the stamped tree, made only on click because signed-out users get 60 an hour, and it fails for a stamp whose commit was never pushed.
